System design · homepage agent

Thirty Seconds

A visitor types a company's website on the homepage. About 30 seconds later they get a shareable page describing the 3 to 5 AI agents Davin would build for that company. Behind it sits one Next.js API route that reads the site, makes two or three Claude calls in a fixed order, checks the result, and saves it to Redis.

Entry POST /api/blueprint Models Claude Haiku 5.5 · Claude Sonnet 5.5 Deadline 60 s per run Output /b/{slug}

One run, start to finish

  1. The visitor submits a URL

    BlueprintLauncher posts { url } as JSON and reads the response body as a stream. Without JavaScript the same form posts normally and gets a 303 redirect to the result or to /sorry/{code}.

  2. The handler runs the cheap checks first

    Body size, same-origin, honeypot, a 10-per-minute flood guard, then URL normalization (no IP literals, platform hosts or the site itself). A domain seen in the last 7 days returns its cached blueprint at once. Only then does it take a per-visitor run, a global run, a $0.15 budget reservation and a per-host lock.

  3. Read the site

    Fetches the homepage and up to 3 same-site pages scored by link text (about, pricing, products), in parallel. Parked domains, bot challenges and thin pages are detected here.

  4. Research Haiku 5.5

    Scraped text is wrapped as untrusted <website_content> and turned into a typed profile: offerings, customers, business model, operations, scale signals, a fit verdict and safety flags. If the site blocked the bot or said too little, a web search writes a brief and research runs again with it.

  5. Design Sonnet 5.5

    Sees only the profile plus a catalog of Davin's past projects. Streams 3 to 5 agents, each with a trigger, actions, read/write tools, a human approval gate and the evidence behind it, then a first build and caveats. Agent names are picked out of the partial JSON and shown live.

  6. Check and save

    Plain code checks the draft: at least 3 distinct agents, evidence on each, at least one human gate, the company or two offerings named, no URLs, emails or phone numbers. A failed draft gets one redraft with the failures listed, if 20 seconds remain. The result and a cost receipt are written to Redis.

  7. Hand off to the blueprint page

    The stream ends with done, the browser goes to /b/{slug}, and that page renders on the server from Redis and stays cached for 5 minutes.

A pipeline, not an open-ended agent loop

The order of steps is fixed in code. Claude is called 2 times on a normal run and at most about 6 on the worst path, and every answer must match a Zod schema. The only tool a model touches is Anthropic's hosted web search in the fallback. That keeps cost, time and failure modes bounded.

Guardrails

Cost

  • Every run reserves $0.15 against a monthly cap ($10 by default), then settles to the real token and search cost.
  • 40 runs a day site-wide and 3 per visitor, keyed by a salted hash of the IP.
  • Failures that aren't the visitor's fault (timeouts, provider errors, quality) give the run back.
  • THIRTY_LIVE=off stops new runs without a redeploy. Cached and example blueprints keep working.

Safety

  • DNS answers are checked against private and reserved ranges at connect time. IP literals are refused and every redirect is re-checked, 4 hops at most.
  • Scraped < and > are neutralized so page text can't close the prompt's tags. Injection attempts are flagged and logged, never followed.
  • Adult or illegal businesses stop as unsafe, model refusals as declined.
  • The design model never sees raw page text, only the extracted profile.

Reliability

  • The run is kept alive with after(), so it finishes and is saved even if the visitor closes the tab.
  • A per-host lock means two people entering the same domain share one run. The second waits and polls for up to 60 s.
  • Not-a-company, unreachable and unsafe results are cached for 24 h so they aren't paid for twice.
  • Redis calls time out at 3 s. In development an in-memory store stands in.
